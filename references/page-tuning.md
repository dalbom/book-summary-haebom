# 페이지 수 맞추기 루프

## 원칙: 강제 페이지 나누기로 맞추지 말 것

RED baseline이 드러낸 핵심 실패: 사용자가 "5페이지"라고 하면, 에이전트가 `PB()` 4개를 넣어 강제로 5페이지를 만든다. 결과는 썰렁한 반 페이지·빈 공간·부자연스러운 장 분할.

**올바른 방식:** 콘텐츠는 자연스럽게 `Sep()` 로만 흐르게 하고, **실제 렌더링 페이지 수를 측정**해서 부족하면 채우고 넘치면 줄인다.

## 원칙: 자수는 사실·풍경·대사 디테일로만 채운다

페이지 부족이 발견되면 가장 흔한 실패 모드 두 가지:

1. **같은 표현을 여러 번 박아 부풀리기** — "한 자리/한 줄로/한 박자/한 평생" 같은 의미 없는 구절이 단락에 3회 이상 폭주. 작품마다 폭주하는 구절이 다르다 (실측에서 한 작품 첫 빌드에 "한 X" 패턴이 540건 발견된 사례 — `references/ai-ness-ko.md` §11c 참조). 진단: 한 단락에 같은 어휘/구절이 3회 이상이면 즉시 humanize.
2. **이미 묘사된 사건을 다른 단락에서 다시 풀기** — facts.md에 한 번 박힌 사건이 다른 챕터에서 또 자세히 묘사된다. 진단: 새 단락이 묘사하는 사건이 facts.md의 다른 챕터 비트에 있는지 확인하고, 있으면 한쪽은 한 줄 요약으로만 둔다.

**올바른 방식:** 자수가 부족하면 새 사실·풍경·대사 디테일을 추가한다. **같은 표현으로 부풀리거나 이미 있는 사건을 또 풀지 않는다.**

## 루프

```bash
bash ~/.claude/skills/book-summary-haebom/scripts/build_and_check.sh {작품명}_요약.docx <target>
```

스크립트가 하는 일:
1. `node build.js` → .docx 생성
2. `soffice --headless --convert-to pdf` → .pdf 변환
3. `pdfinfo | grep Pages` → 실제 페이지 수
4. target과 비교, delta 리포트

**목표 허용 오차: ±1 페이지**

## 부족할 때 (target > current)

차이가 2-3페이지면: 다음 중 하나.
차이가 4페이지 이상이면: 여러 개 조합.

**⚠️ 새 P() 블록을 추가했으면 그 즉시 직전·신규·직후 3-단락을 한 호흡으로 재독한다 (SKILL.md Step 7-1).** 다음 네 가지를 확인:
1. **도입 문장 중복** — 인접 단락이 같은 주제를 두 번 부르는지 (서로 다른 두 작업에서 똑같이 사후로 잡힌 결함)
2. **사건 중복 묘사** — 새 단락이 묘사하는 사건이 facts.md의 다른 챕터 비트에 이미 있는지 (실측에서 한 작품에 4건이 한꺼번에 사후로 잡힌 사례)
3. **시점/환상-현실 모호** — 새 단락이 누구 시점인지·환상인지 실제 행동인지 인접 단락에서 자연스럽게 이어지는지 (추가 단락이 환상인지 실제인지 모호하다는 지적이 실측에서 발생)
4. **단락 내 동일 구절 폭주** — `한 자리/줄/박자` 같은 의미 없는 구절이 3회 이상 박혔는지

지금 잡으면 Step 10 통독 점검 부담이 준다.

**⚠️ 시간 표지 수동 점검** — 페이지 튜닝 다중 패스 후, 시간 표지(Sol N, N년 후, 며칠 후, 다음 날, 연도 등)가 있는 작품이면 챕터 안에서 단조 증가하는지 한 번 훑는다. 일지 형식 작품에서 시간 표지가 도치된 결함(495일 → 516일 → 490일 식)이 정확히 이 단계를 거치며 실측에서 발생했음. 도치된 단락이 보이면 facts.md의 챕터 단락이 명시한 시간 순서를 기준으로 재배열.

### 1. 대화 장면 확장 (+1-2쪽)
- 요약된 대화를 원작 대사 흐름으로 복원
- 반응 묘사 추가 (`~라는 말을 듣고 어린 왕자는 한참 말이 없었어요. 바람이 모래를 살짝 쓸고 지나갔지요.`)

### 2. 감정 묘사 문단 추가 (+0.5-1쪽)
- 주인공의 내적 독백을 1-2문단 삽입
- 서술자가 독자에게 말 거는 한 문장 ("~라는 마음, 너도 느껴 본 적 있니?")

### 3. "이야기 속의 이야기" 삽입 (+2-4쪽) — **단, 원작에 근거 있을 때만**
- 원작에 편지·일기·구전이 있으면 전문 복원
- **없으면 이 방법 쓰지 말 것.** 억지 창작은 원작 훼손

### 4. 부록 확장 (+0.5-1쪽)
- 어려운 단어 개수 늘리기 (3개 → 8개)
- 토론 질문 추가 (3개 → 7개)
- 부록 간 1행 줄바꿈 → 짧은 설명 추가

### 5. 장면 묘사 디테일 추가 (+0.5-1쪽)
- 날씨·계절·소품·냄새·소리 중 한두 가지를 문장에 추가
- 예: `어린 왕자는 장미를 바라봤다.` → `어린 왕자는 아침 이슬이 살짝 맺힌 장미를 가만히 바라봤어요. 장미에서 달콤한 향기가 은은하게 풍겨 왔지요.`

### 6. 챕터 분할 (+1쪽 정도)
- 긴 챕터 하나를 두 챕터로 나눈다 (예: 5장 → 5장 + 6장)
- 이건 구조 변경이라 신중히. 원작 흐름이 자연 분할되는 지점에서만.

## 초과할 때 (current > target)

### 1. Note 블록 축소 (-0.5쪽)
- 여러 Note 박스를 하나로 통합
- Note를 일반 문단으로 녹이기

### 2. 중복 묘사 제거 (-0.5-1쪽)
- 같은 감정·상황을 두 번 묘사한 곳 찾기
- 두 번째 묘사를 짧게 축약하거나 삭제

### 3. 대화 압축 (-0.5-1쪽)
- 긴 대화를 요약 서술로 바꾸기
- 예: `"가자." "어디로?" "저쪽." "왜?" "그냥."` → `어디로 가느냐고 묻는 폴에게 어린 왕자는 그냥 저쪽이라고만 답했다.`

### 4. 챕터 통합 (-1-2쪽)
- 짧은 챕터 두 개를 하나로 합침
- 중간 `✦` 구분자 제거

### 5. 등장인물 소개 / 들어가는 말 축약 (-0.3-0.5쪽)
- 등장인물 소개에서 부차 인물 삭제
- 들어가는 말을 한 문단으로 압축

### 6. 토론 질문 개수 축소 (-0.3쪽)

## 절대 하지 말 것

| ❌ 금지 | 왜 |
|---|---|
| 빈 페이지 / 빈 단락으로 채우기 | 인쇄물 기준 품질 저하 |
| 폰트 크기 / 줄 간격을 페이지 맞추려고 조정 | 독자 연령 기준이 흐려짐. 연령 기준으로만 결정 |
| 여백(margin)을 페이지 맞추려고 조정 | 동일 이유 |
| 원작에 없는 "이야기 속의 이야기" 창작해 삽입 | 원작 훼손 |
| 본편을 잘라 부록으로 보내기 | 독자 혼란 |
| `PB()` 를 장 사이에 강제 삽입 | 한국 책 관례 위반, 여백 낭비 |

## 수렴 전략

처음 빌드 결과가 target ±5페이지 안쪽일 가능성이 높다면:
- **한 번에 하나씩** 조정하고 재측정
- 예상 페이지 추가량을 확인해 가며 진행

| 조정 | 실측 평균 페이지 변화 |
|---|---|
| 챕터 하나에 감정 묘사 1문단 추가 | +0.3-0.5쪽 |
| 챕터 하나에 대화 장면 추가 | +1-1.5쪽 |
| 부록 단어 5개 추가 | +0.3쪽 |
| 토론 질문 3개 추가 | +0.3쪽 |
| "이야기 속의 이야기" 한 편 추가 | +2-3쪽 |
| 챕터 하나 분할 | +0.5-1쪽 |
| 챕터 둘 통합 | -1-1.5쪽 |
| 중복 묘사 하나 삭제 | -0.3-0.5쪽 |
| 긴 대화 요약화 | -0.5-1쪽 |

## 빌드 실패 시

- `soffice` 미설치: `brew install --cask libreoffice`
- `pdfinfo` 미설치: `brew install poppler`
- `docx` npm 미설치: `npm install docx` (템플릿에 포함된 package.json 참조)
