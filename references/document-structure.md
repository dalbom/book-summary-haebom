# 문서 구조 표준 템플릿

요약본 .docx의 표준 골격. 사용자와 합의한 연령대·페이지 수에 맞춰 섹션을 가감한다.

## 기본 골격 (10개 섹션)

| # | 섹션 | 페이지 예상 (30-40쪽 기준) | 필수 여부 |
|---|---|---|---|
| 1 | 표지 | 1쪽 | 필수 |
| 2 | 목차 | 0.5-1쪽 | 선택 (20쪽 미만이면 생략) |
| 3 | 들어가는 말 | 0.5-1쪽 | 필수 |
| 4 | 등장인물 소개 | 0.5-1쪽 | 필수 (2인 이하일 땐 생략) |
| 5 | 본편 챕터 | 20-32쪽 | 필수 |
| 6 | 이야기 속의 이야기 | 2-4쪽 | **원작에 액자가 있을 때만** |
| 7 | 끝맺는 말 | 0.5-1쪽 | 선택 (§7 — 본편 마지막이 이미 closing이면 생략) |
| 8 | 부록 1: 어려운 단어 사전 | 0.5-1쪽 | 아동·청소년 대상 필수 |
| 9 | 부록 2: 같이 이야기해 볼 거리 | 0.5-1쪽 | 아동·청소년 대상 필수 |
| 10 | "— 끝 —" | 0.5쪽 | 필수 |

## 연령별 변형

### 초등 저학년 (1-3학년) 대상

- **분량**: 20-30쪽이 상한. 더 길면 안 읽는다.
- **폰트 크기**: 본문 12pt (다른 연령보다 1pt 크게)
- **줄 간격**: line 360 (조금 여유 있게)
- **챕터 길이**: 한 장당 1.5-2.5쪽
- **대화 비중**: 40% 이상 권장
- **의성어·의태어**: 적극 사용
- **어려운 단어 사전**: 필수. 한자어·추상어 전부 풀이
- **토론 질문**: 3-4개. 짧고 구체적 ("가장 좋아하는 장면은?" 같은)
- **표지**: 부제 권장 ("별에서 온 작은 친구의 이야기" 같은)

### 초등 고학년 (4-6학년) 대상

- **분량**: 30-50쪽
- **폰트 크기**: 본문 11pt
- **줄 간격**: line 320
- **챕터 길이**: 한 장당 2-3쪽
- **대화 비중**: 30-40%
- **어려운 단어 사전**: 필수. 한자어·관용구 중심
- **토론 질문**: 4-6개
- **도입부**: 원작자·배경 간략 소개 OK

### 청소년 대상

- **분량**: 40-70쪽
- **폰트 크기**: 본문 10.5-11pt
- **줄 간격**: line 300
- **챕터 길이**: 한 장당 3-5쪽
- **어려운 단어 사전**: 선택 (사자성어·개념어만)
- **토론 질문**: 5-8개. 주제 심화형
- **도입부**: 원작 배경·시대 맥락 설명
- **민감 콘텐츠**: 사용자가 원하면 원작대로 유지 가능

### 성인 대상

- **분량**: 50-100쪽
- **폰트 크기**: 본문 10.5pt
- **줄 간격**: line 280-300
- **챕터 길이**: 유연
- **어려운 단어 사전**: 불필요 (고어·전문 용어만 선택적으로)
- **토론 질문**: 심화형, 선택
- **도입부**: 번역본·역자 언급, 시대 배경, 원작의 문학적 위치

## 초단편 가이드 (≤10쪽)

사용자가 5쪽·7쪽·10쪽 같은 짧은 분량을 요청하면 기본 10섹션 구조를 **그대로 쓰면 본편이 1-2쪽으로 밀려서 이야기가 뼈대만 남는다.** 아래 축약 구조로 전환한다.

### 축약 원칙

1. **한 섹션에 한 페이지를 통째로 쓰지 말 것.** 표지·들어가는말·등장인물을 모두 붙여서 1-2쪽 안에 마무리.
2. **부록은 간소화 또는 통합.** 어려운 단어 사전 + 토론 질문을 한 섹션으로 합쳐 "부록: 더 알아보기"로.
3. **내부 `PB()`는 최소화.** 표지 다음에만 `PB()`, 나머지는 `Sep()` 혹은 빈 단락으로 흐름 유지.
4. **본편 비중 60% 이상 확보.** 독자가 원한 건 이야기 요약이지 표지·부록이 아님.

### 분량별 권장 구조

| 목표 페이지 | 권장 섹션 구성 |
|---|---|
| 3-5쪽 | 표지(반쪽) + 들어가는말(반쪽, 등장인물 요약 통합) + 본편 2-3장 + "— 끝 —"(반쪽) |
| 6-8쪽 | 표지(1쪽) + 들어가는말+등장인물(1쪽) + 본편 3-5장 + 부록 통합(반쪽) + "— 끝 —" |
| 9-10쪽 | 표지(1쪽) + 들어가는말(반쪽) + 등장인물(반쪽) + 본편 5-6장 + 부록 통합(1쪽) + "— 끝 —" |

### 구체 예시 — 5쪽 초등 고학년용 『어린 왕자』

```
[표지 + 부제: 반쪽]
[들어가는말 + 등장인물 2명: 반쪽]
[본편 1장 - 사막의 만남: 1쪽]
[✦ Sep]
[본편 2장 - 장미와 여우: 1.5쪽]
[✦ Sep]
[본편 3장 - 이별과 별빛: 1쪽]
[— 끝 — + 부록 1줄씩(단어 3개, 질문 2개): 반쪽]
```

### PB 개수 규칙

| 목표 페이지 | 내부 PB 개수 권장 |
|---|---|
| ≤5쪽 | **0개** (표지 다음 1개만, Sep으로 흐름) |
| 6-10쪽 | **1-2개** (표지 후 + 부록 진입 전) |
| 11-20쪽 | 2-3개 |
| 21쪽+ | 기본 템플릿 그대로 (4-5개) |

### 부록 통합 예시

별도 섹션이 아니라 "— 끝 —" 바로 앞에 간소하게:

```
📖 이야기를 덮기 전에
  · 어려운 말: 소행성 · 길들이다 · 허영가
  · 같이 이야기해 볼 거리: 나를 '길들인' 존재는 누구일까? / 가장 기억에 남는 어른은?

                                    — 끝 —
```

### 초단편 시 "이야기 속의 이야기" 금지

원작에 액자가 있더라도 ≤10쪽에서는 생략한다. 본편이 우선.

## 섹션별 쓰기 가이드

### 1. 표지

`Cover({ title, author, originalTitle, subtitle })` 헬퍼가 처리. 부제는 독자 감성에 맞춰 (예: 어린 왕자 → "별에서 온 작은 친구가 남긴 말").

### 3. 들어가는 말

원작을 처음 만나는 독자에게 책을 소개하고, 본문을 펼치고 싶게 만드는 한두 단락. **요약본 제작 메타가 아니라 책 소개 글**이다.

**반드시 들어가야 할 것:**

1. **원작 제목** — 한국어 제목과 원어 제목 (번역본을 옮겼다면 이 사실까지)
2. **원저자**
3. **원작 출간 연도**
4. **도입부 후크** — 책 1-2장에서 무슨 일이 벌어지는지 한두 단락으로 추려 호기심 자극. 결말이나 핵심 반전은 흘리지 않는다.

**절대 넣지 않을 것** (— 정확히 이 잡음이 실제 배송본에서 사용자가 직접 잘라낸 패턴):

- 원작 몇 장 → 요약본 몇 장으로 줄였다는 비율
- 1인칭/3인칭 등 서술 시점 정보
- 어떤 장면을 어떻게 순화했는지에 대한 편집 노트
- 어려운 단어 사전·이야기 나눌 거리·과학 용어 처리 같은 부록 안내

이런 메타 정보는 결정한 사용자 본인이 이미 알고, 책을 펴는 독자에게는 잡음일 뿐이다. 부모/교사가 원작과의 차이를 궁금해할 만한 한 줄 정도가 정말 필요하면 끝맺는 말 마지막에 짧게.

**아동·청소년 대상일 때 주의:** 어른 대상 묘사·로맨스 같은 정황은 단어로 직접 적지 말고 어떤 장면이 펼쳐지는지 구체 이미지로만 안내한다. (예: "성인 대상 로맨스 장면이 있어요" → "두 사람이 처음 만나 마음이 흔들리는 카페 장면")

**예시 (『프로젝트 헤일메리』, 초등 고학년 톤):**

```
앤디 위어가 2021년에 펴낸 SF 소설 『Project Hail Mary』를 어린이 독자를 위해
다시 옮겼어요. 같은 작가의 『마션』처럼 과학과 우정이 함께 굴러가는 이야기예요.

주인공 그레이스는 어느 날 자기 이름조차 떠올리지 못한 채 우주선 한가운데에서
눈을 떠요. 옆자리에는 친구 두 사람이 죽은 채 누워 있고, 지구는 까마득히 멀어요.
그가 왜 여기에 있는지, 무엇을 해야 하는지 — 잃어버린 기억을 한 조각씩 되찾으면서
조금씩 알아 갑니다.
```

### 4. 등장인물 소개

- 2-6명 이내
- 한 인물당 3-5줄
- 이름 + 나이·역할 + 성격 + 이야기 속 위치

예:
```
어린 왕자
  먼 별 B612에서 온 작은 소년. 호기심이 많고 장미 한 송이를 깊이 사랑한다.
  별들을 떠돌며 어른들의 세계를 들여다본다.

조종사 아저씨
  사막에 불시착한 비행기 조종사. 어른이 되었지만 어릴 적 마음을 잃지 않았다.
  어린 왕자의 친구이자 이야기의 목격자.
```

### 5. 본편 챕터

- 각 챕터 시작: `H1` 으로 장 번호 + 제목
- 챕터 끝에 `Sep()` (✦ ✦ ✦) — 페이지 나누기 아님
- 첫 챕터 앞에만 `PB()` (표지·목차·등장인물 소개 뒤)
- 마지막 챕터 끝에 `Sep()` 한 번 더 찍고 이어지는 섹션으로

**원작 챕터를 그대로 옮길지 합치는지는 Step 2 질문 #4에서 합의.**
페이지 수 맞추기 위해 억지로 챕터를 쪼개거나 합치지 마라 — 이야기 흐름 단위로 결정.

### 6. 이야기 속의 이야기 (조건부)

**원작에 액자 구조나 삽화가 있을 때만 포함.** 없는 작품에 강제로 넣지 마라.

포함하는 경우 구분:
- 『폴리아나』 → 아빠의 편지, 목사님 설교 원문 등
- 『이상한 나라의 앨리스』 → 토끼굴 속 여왕의 이야기 재구성 OK
- 『어린 왕자』 → 없음. 넣지 마라.

형식: `H2` 로 "이야기 속의 이야기 — [제목]" 표기. 본편과 구분되는 톤(일기, 편지, 구전 설화 형식)으로 써서 액자임을 명시.

### 7. 끝맺는 말 (옵션)

**섹션 자체가 옵션이다.** 본편 마지막 단락이 이미 자연스러운 작품 마무리·여운 역할을 하면 별도 끝맺는 말 섹션은 생략한다 (특히 어른용·청소년용 작품, 또는 마지막 챕터가 강한 closing shot인 작품). 본편 마지막이 이미 마무리 역할을 하는데 끝맺는 말 섹션을 덧붙였다가 사용자가 중복으로 보고 삭제를 요청한 실측 사례.

**섹션을 둘 경우의 내용:**
- 작품 전체의 여운을 정리
- 독자에게 직접 말 건네는 문장 1-3개 (예: "이 이야기를 읽은 네가...")
- 원작자 소개 한 문단 (아동·청소년 대상이면 필수)

**판단 기준:** 본편 마지막 챕터가 사실 묘사로만 끝나면 끝맺는 말 두기. 마지막 단락이 이미 작품의 메시지·여운을 담은 closing이면 생략하고 본편 마지막에 모든 마무리를 둔다.

**메타 표현 금지** — 끝맺는 말에서만 "독자에게 말 거는 자리"가 허용된다. 본편 안에서 외부 시청자·관객·독자를 직접 호명하지 말 것. "영화를 끝까지 본 사람은…", "책을 읽는 너희는…" 같은 표현이 본편 챕터에 들어가면 작품 안과 밖이 섞인다 (본편에 관객 호명이 박혀 사용자 지적 후 삭제된 실측 패턴).

**작중 비유 룰** — 인물 대사는 원작 사실에 한정. 원작에 없는 비유("수평선만 보지 마", "풍선을 떠나는 마음으로" 같은 어시스턴트가 만든 표현)는 인물 입에 직접 박지 말고 서술자 톤으로만 풀 것. facts.md §작품 정보 항목 참조.

### 8. 부록 1: 어려운 단어 사전

- 가나다순
- 본문에 등장한 순서 표시 권장 ("(3장)")
- 풀이는 어린이가 이해할 수 있는 일상어로

예:
```
소행성 (3장)
  태양 주위를 도는 아주 작은 별. 행성보다 작고 둥글지 않을 때도 있어요.

길들이다 (4장)
  원래 이 말은 "야생 동물을 사람에게 익숙하게 만들다"라는 뜻이에요.
  어린 왕자와 여우는 "마음을 주고받아 서로에게 특별해진다"는 뜻으로 썼어요.

허영가 (3장)
  사실이 아니어도 자기를 대단한 사람으로 보이려고 꾸미는 사람.
```

### 9. 부록 2: 같이 이야기해 볼 거리

- 질문 형식. 답이 정해지지 않은 것.
- 주인공 감정 / 작품 주제 / 독자 자신의 경험 / 만약 ~라면
- 3-8개 (연령대에 따라)

### 10. — 끝 —

- 가운데 정렬
- `— 끝 —` 만 크게 배치
- **PB()를 넣지 않는다.** 부록 2 뒤에 이어서 배치. 빈 페이지가 생기면 오히려 허전하다.
- 여백으로 마무리 여운

## 모듈식 빌드 (≥20쪽 작업 권장)

긴 분량 작업에서 단일 `build.js`에 1,000+ 줄 children 배열을 만드는 방식은 다음 문제를 만든다:

1. 컨텍스트 한계로 본문 작성이 다중 패스로 끊기면, "클라이맥스 먼저 박고 사이 채우기" 패턴이 자연스럽게 발생 → 시간 도치 버그
2. 페이지 예산이 "총합"으로만 존재해서 한 챕터가 부풀면 다른 챕터를 깎음
3. 한 챕터만 고치려 해도 전체를 스크롤해야 함

해결책은 LaTeX 논문처럼 **섹션별 분리 + 메인 조립자**.

### 디렉터리 구조

`assets/modular/` 골격을 통째로 복사해서 시작:

```bash
cp -r ~/.claude/skills/book-summary-haebom/assets/modular/* books/{작품명}/
```

│   ├── _template.js      # 무시됨 (앞 _ )

```js

```

**원칙:**

1. **상단 주석에 TARGET 자수와 시간 범위 명시.** budget.js 출력값을 그대로 복붙.
2. **한 번에 끝까지 쓰고 통독 후 다음 챕터로.** 시간 도치를 막는 가장 강력한 방어선.
3. **챕터 사이 `Sep()`/`PB()` 직접 호출 금지.** build.js가 자동 삽입.
4. **TARGET ±10% 안에서 마무리.** 다른 챕터에서 빌리지 않는다 — 해당 챕터 안에서 압축/확장.

### main build.js 조립 패턴

```js
const helpers = require('./helpers');
helpers.setSettings({ FONT_BODY: 'Apple SD Gothic Neo', BODY_SIZE: 22, ... });

// setSettings 후 require — 모듈들이 갱신된 SETTINGS를 본다
const cover = require('./front/cover');
// ...

// chapters/*.js 자동 발견 (파일명 정렬, _로 시작하는 파일은 무시)
const chapterFiles = fs.readdirSync(chaptersDir)
  .filter(f => f.endsWith('.js') && !f.startsWith('_'))
  .sort();

const children = [
  ...cover, PB(),
  ...intro, PB(),
  ...characters, PB(),
];
chapterFiles.forEach((f, i) => {
  children.push(...require(path.join(chaptersDir, f)));
  if (i < chapterFiles.length - 1) children.push(Sep());
});
children.push(...ending, PB(), ...glossary, PB(), ...questions, ...endPage);
```

### 페이지 튜닝 시

`build_and_check.sh`로 페이지 수 확인 후 차이가 나면:
- **부족할 때**: 가장 가벼운 챕터(낮은 가중치)에 단락 추가. 모든 챕터에 균등하게 흩뿌리지 말 것.
- **초과할 때**: 가장 무거운 챕터부터 압축. 챕터 단위로 작업해서 도치 위험 없음.
