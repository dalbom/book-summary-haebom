# 단일 진실 저장소 — facts.md

## 왜 필요한가

요약본 작성은 본질적으로 **다중 패스**다. 골격 → 챕터 → 페이지 튜닝 → 번역투 패스 → AI-ness 패스 → 통독. 패스마다 같은 사실(캐릭터 나이·관계·소품·세계관 룰·서술자 시점·핵심 플롯 비트)을 모델이 다시 떠올려 본문에 반영해야 한다. 진실 저장소가 없으면 패스마다 미세하게 표류한다.

실측에서 기록된 결함 유형:
- **핵심 비트 누락** — 작품의 뼈대가 되는 사건(동력원 전환, 주인공의 비자발적 탑승 같은)이 챕터 통합 과정에서 빠짐
- **서술자 시점 누설** — 1인칭 화자가 "1장에서 내가 눈을 뜬"이라고 챕터 번호를 인용
- **세계관 룰 위반** — 시각이 없는 종족이 "등을 깜빡이는 걸 봤다"는 식으로 의사소통
- **캐릭터 모순** — 막내라던 캐릭터가 "내 동생들"을 호명, 다리 없는 캐릭터가 "일어섰다", 등장한 적 없는 캐릭터가 결말에 호명
- **시간 표지 도치** — 일지 형식 작품에서 페이지 튜닝 다중 패스 중 단락이 비순차로 박힘

`facts.md` 한 파일이 위 결함 중 앞 4건(핵심 비트·시점·세계관 룰·캐릭터)을 작성 전 단계에서 차단한다. 시간 표지 도치는 별도로 `references/page-tuning.md` §"수동 점검"이 담당.

## 위치

`books/{작품명}/facts.md`. build.js 옆. docx에 포함되지 않는 메타 파일.

## 형식 (베이스: `assets/modular/facts_template.md`)

```markdown
# {작품명} — facts

## 작품 정보

- **원작**: {원저자} 『{원제}』 ({출간 연도})
- **번역본 출처**: (한국어 번역본 기준이면 제목·역자, 영문 직접 번안이면 비워둠)
- **서술자 시점**: (1인칭 / 3인칭 / 액자 / 혼합 — 1인칭이면 화자 이름 명기)
- **세계관 룰**: (디폴트 상식과 다른 물리·생물·사회 룰. 일반 작품이면 비워둠)
- **작중 비유 룰**: 인물 대사는 원작 사실에 한정. 원작에 없는 비유는 서술자 톤으로만.
- **외부 호명 금지**: 작중에서 관객·시청자·독자를 직접 호명하지 말 것. 끝맺는 말 등 명시적 자리에서만.

## 표준 용어·명대사 (옵션, 원작에 한국어 정식 번역본·자막이 있을 때 필수)

원작에 정식 한국어 자막·번역본이 있으면 그 표준 용어와 주요 명대사를 여기에 옮긴다. 작업 중 임의 의역 금지 — 표준 의미와 어긋나지 않게 인용한다.

- **고유명사·핵심 개념어 카탈로그**: 한 줄씩 (예: `Event Horizon → 사건의 지평선`)
- **주요 명대사** 5~10개: 원문 + 표준 한국어 형태

원작이 한국어 창작이거나 정식 번역본이 없으면 비워둔다. 영화 각색 작품에서는 한국 자막의 표준 번역을 따르는 게 안전 (Event Horizon이 표준 "사건의 지평선" 대신 "사상의 지평선"으로 옮겨진 혼선, 명대사 의미가 반대로 뒤집힌 의역이 실측에서 발생).

## 등장인물

각 인물 정보에 **나이·세대·인물 간 톤**까지 명시한다. 임종·세대 도약 작품에서 자식·손자 세대 나이가 산수상 어색해지는 일을 막는다.

- **{이름1}** — 역할·핵심 특성·소품·관계
  - 시점별 나이: (예: 출발 35세 / 재회 124세)
- **{이름2}** — ...

### 세대별 나이 표 (시간 도약 ≥1세대 발생 작품일 때 필수)

임종 자리·장기 시간선·"수십 년 뒤" 같은 도약이 있으면 자식·손자 세대 나이를 산수로 검증한다.

| 인물 | 시점 | 나이 |
|---|---|---|
| 주인공 | 출발 | 35 |
| 주인공 | 임종 | 124 |
| 주인공 자식 | 임종 자리 | 80~90 |
| 주인공 손자 | 임종 자리 | 60대 |

빠뜨리면 "주인공 124세인데 자식이 60대?" 같은 모순이 사후에 발견된다 (실측 사례).

### 인물 간 톤 표 (한국어 작품 필수)

같은 두 인물의 대사 톤(반말/존댓말)·호칭이 챕터마다 바뀌는 것을 막는다.

| 화자 → 청자 | 톤 | 호칭 | 비고 |
|---|---|---|---|
| 주인공 → 동료 | 반말 | 너 | 첫 항해 이후 |
| 주인공 → 상관 | 존댓말 | 박사님 | |

같은 두 인물 사이 톤이 챕터 4와 5에서 다른 결함이 실측에서 사용자 지적으로 사후 발견됐다.

## 챕터별 핵심 비트

### 1장. {제목}

{시간 표지}. {핵심 사건}. {결말 또는 다음 장으로의 연결}.

### 2장. {제목}

...
```

## 작성 절차 (Step 5)

1. **assistant 초안**: Step 4(문서 골격)가 끝나면 assistant가 사용자 인터뷰 응답 + 원작 지식을 종합해 `books/{작품명}/facts.md`를 위 형식으로 작성한다.
2. **사용자 confirm**: 사용자에게 파일 경로를 알려 주고 검토 요청. 누락된 plot beat·잘못된 캐릭터 정보·잘못된 세계관 룰을 이때 잡는다.
3. **수정 반영**: 사용자가 고치면 그대로 진행. 챕터 본문은 confirm 받은 facts.md를 읽고 작성.

원작을 모르는 책(Step 0 NO 경로)이면 사용자가 줄거리를 공유한 시점에 그 정보를 그대로 facts.md에 옮기고 confirm 요청. 빠진 부분이 있으면 사용자가 추가 입력.

## 작성 시 의무

- **모든 챕터 본문 작성 전에 facts.md를 먼저 읽는다.** 챕터 한 개 = 그 챕터 facts 단락 한 개를 충실하게 풀어낸 결과.
- **세계관 룰을 어기는 비유** ("시각 없는 종족이 깜빡이는 등을 봤다") 금지.
- **서술자 stance 누설** ("X장에서 내가 ...", "이 책에서는 ..." 같은 메타 표현) 금지. 1인칭이면 책 자체를 호명하지 않는다.
- **작중 외부 호명 금지**: "영화를 끝까지 본 사람은…", "책을 읽는 너희는…" 같은 표현이 본편 챕터에 들어가면 작품 안과 밖이 섞인다. 끝맺는 말처럼 명시적으로 독자에게 말 거는 자리에서만 허용.
- **인물 대사는 원작 사실에 한정**: 원작에 없는 비유를 작중 인물 입에 박지 말 것. 비유는 서술자 톤으로만 풀고, 임의 창작 대사는 facts.md에 명시적으로 추가한 뒤 사용.
- **캐릭터 정보 충돌**: 챕터 본문이 facts.md와 다른 사실을 말하면 본문이 틀렸다는 신호 — 본문을 고친다.
- **표준 용어·명대사 인용**: facts.md §표준 용어가 있으면 그대로 인용. 임의 의역 금지.

## 갱신 룰

작업 중 사용자가 facts(캐릭터·세계관·플롯 비트)를 바꾸고 싶어하면:

1. **facts.md를 먼저 수정**.
2. 영향 받는 챕터를 재작성.
3. **본문에서 fact를 바꾸지 않는다.** 단일 진실 저장소가 본문보다 항상 앞선다.

이 순서를 어기면 자기 모순이 누적된다 (실측에서 반복 확인된 패턴).

## 카운트 정합성

- **`### N장.` 헤더 개수 = `chapters/*.js` 파일 개수**.
- 어긋나면 모듈식 build.js가 시작 시 경고 출력. 작업 흐름은 막지 않음 — 사용자가 결정.
- 사용자가 챕터를 분할·통합한 후 facts.md 갱신을 잊지 않게 하는 안전망.

## 무엇을 facts.md에 두지 않는가

- **본문 문장 자체** — 본문은 chapter 파일에. facts.md는 plot beat 한 단락만.
- **페이지·자수 예산** — `assets/modular/chapters/_template.js` 상단 주석에. budget.js 결과는 챕터 파일 안.
- **삽화 프롬프트** — `{작품명}_삽화_프롬프트.md` 별도.
- **인터뷰 응답 메타** — 사용자 본인이 결정한 톤·연령·민감 처리 같은 메타는 build.js 상단 주석으로 충분 (들어가는 말에는 절대 적지 않음).

facts.md는 **읽는 사람이 책의 사실을 잃지 않게 하는 단일 페이지**. 그 이상도 이하도 아니다.
